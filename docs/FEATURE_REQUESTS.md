# 新功能需求模板

> 不要只说“加个玩法”。一页写清：玩家做什么、系统怎么变、失败怎么办、怎么验收。

---

## 1. 一页模板

```markdown
# FEAT-XXX：功能名称

## 一句话
玩家在什么情况下，用什么，得到什么新体验？

## 触发条件
什么时候能用？按什么？拖什么？

## 费用
工作内存 / 碎片 / 次数 / 冷却？

## 目标
自己 / 敌人 / 边 / 区域 / 坏死格？

## 规则
成功发生什么？失败发生什么？退不退费？

## 与现有机制的交互
WEAK / LINK / GC / 护盾 / ALIAS / 坏死格 / 画质 / Boss 免疫？

## 数值
基础值、++ 值、持续时间、半径、上限。

## 表现
颜色、特效、音效、HUD 位置、文字。

## 不包含
这次明确不做什么。

## 验收
- [ ] 正常路径
- [ ] 无效目标
- [ ] 资源不足
- [ ] 18 关流程不破
- [ ] 教程不破
- [ ] `run_all.py` 通过
```

---

## 2. 按角色拆单

跨层功能拆成四张单：

| 单 | 内容 | 验收 |
|---|---|---|
| `[A] 内容` | 卡/敌人/房间数据、数值、奖励池、商店 | `rooms_test` / `CONTENT.md` |
| `[B] 战斗` | 触发、状态机、伤害/GC 交互、失败退费 | `mechanics_test` + 长时模拟 |
| `[C] 表现` | 卡面、拖拽、HUD、特效、音效触发 | `screens_test` + 手窗口 |
| `[D] QA` | 新测试、种子/长时模拟、性能、音频 | `run_all` 全绿 |
| `[Lead] 接口` | 新字段/事件/状态、兼容、合并 | 全量回归 |

---

## 3. 验收写法

不要写“手感好/平衡/有趣”。

要写：

```text
Given：玩家在 R10，画质 30%，有 1 个坏死格
When：按 H
Then：
- 坏死格 -1
- HP +15
- 画质回到 35%
- HUD 出现 +15
- 音效 heal
- 本房不能再次触发
```

## 6. 示例：新卡「回滚」

```text
一句话：把一个敌人回滚到 3 秒前的位置和 HP，用来打断 Boss 蓄力。
费用：2 工作内存
目标：单个敌人
次数：每房 2 次

规则：
- 普通敌人：恢复 HP/位置
- Boss：只恢复位置
- WEAK 标记保留
- ALIAS 只回滚单个成员，不同步血池

分工：A 数据 / B 逻辑 / C 卡面 / D 音效测试
验收：普通敌人恢复、Boss 只回位置、无效目标不消耗、run_all 通过
```
