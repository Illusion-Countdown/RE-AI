> 版本：v0.4 世界观稿  
> 日期：2026-11-22  
> 性质：世界观设定，不是玩法设计  
> 范围：世界结构、五层生态、AI 娘玩家身份、现有玩法的世界观解释、未来内容的概念参考  
> 不含：卡牌效果、敌人数值、地图规则、经济平衡、关卡编成、剧情与对话

## 0. 文档边界

### 0.1 这份文档只回答“世界是什么”

这份文档不设计：

- 新卡牌、新敌人、新 Boss 的具体效果；
- 地图怎么走、commit 有什么代价；
- 经济、掉落、难度曲线；
- 关卡编成和数值平衡；
- 剧情、对话、角色关系。

它只回答：

- 这个世界由哪些层组成；
- 每层的存在法则是什么；
- 每层有什么生态和 Boss 实体；
- AI 娘是谁，她和数据结构是什么关系；
- 现有玩法里的概念，在世界观里怎么解释；
- 以后设计新内容时，可以从哪些概念里取素材。

### 0.2 一句话世界观

> 一台正在下线的计算机，五个抽象层，一棵提交历史；AI 娘在层与层之间穿行，数据结构是她在途中遇到的世界结构。

### 0.3 五条设定原则

1. **每个名词都能在真实计算机里找到对应物。**  
   不做只有赛博外观、没有计算机语义的奇幻设定。

2. **一层只回答一个问题。**  
   层法则、生态、Boss 实体都围绕同一个问题，不堆砌。

3. **AI 娘是角色，数据结构是世界内容。**  
   玩家操控的是 AI 娘，不是链表、数组或树。

4. **现有玩法只解释，不改造。**  
   这份文档不重新设计已经能玩的系统，只给它们一个世界观位置。

5. **Git 是地理，不是规则。**  
   世界的历史结构像提交图，但“怎么走、代价是什么”属于玩法设计，不在这份文档里。

## 1. 世界结构

### 1.1 世界是一台正在下线的计算机

故事发生的世界不是星球，也不是城市，而是一台正在被关闭、迁移或格式化的计算机系统。

它仍然在运行，但已经进入“下线流程”：

- 外层的应用和服务先被关闭；
- 内存开始被回收；
- 内核开始拒绝新的请求；
- 硬件仍在供电，但随时可能断电。

这个状态不需要剧情解释，它只是世界的底色：**所有东西都在被回收，只有提交过的历史还留着。**

### 1.2 五个抽象层

```text
┌────────────────────────────────────────────┐
│ 5  网络层 Network                          │
│    没有全局真相：延迟、丢包、分区、共识      │
├────────────────────────────────────────────┤
│ 4  应用层 Application                      │
│    契约随时变更：API、会话、版本、权限       │
├────────────────────────────────────────────┤
│ 3  运行时层 Runtime                        │
│    无人引用即消失：引用、GC、类型、画质      │
├────────────────────────────────────────────┤
│ 2  内核层 Kernel                           │
│    权限先于存在：句柄、调度、中断、页表      │
├────────────────────────────────────────────┤
│ 1  硬件层 Hardware                         │
│    没有抽象是免费的：电路、总线、时序、散热  │
└────────────────────────────────────────────┘
```

越往下，世界越硬，越接近物理；越往上，世界越软，越接近语义和行为。

“云端”不是第六层，它是网络层的尽头。容器、编排、跨主机复制、遗留系统，都属于网络层的终局区域。

### 1.3 Git 是这个世界的地理

这个世界的历史不是线性的，而是一棵提交图：

- 每一个 `commit` 是一个“地点”；
- 每一条 `branch` 是一条并行的时间线；
- 每一次 `merge` 是两条时间线的汇流；
- 每一次 `revert` 是一道不能完全抹掉的历史疤痕；
- 每一个 `tag` 是一个地标。

这是**地理**，不是玩法规则。

这份文档只说明世界长成这样，不规定玩家怎么移动、commit 有什么代价、merge 怎么冲突。那些属于玩法设计。

### 1.4 层间接口

层与层之间不是楼梯，而是接口：

| 接口 | 世界中的形态 | 含义 |
|---|---|---|
| 硬件 → 内核 | 引导程序 / ABI | 物理信号被翻译成系统调用 |
| 内核 → 运行时 | 加载器 / 系统调用 | 权限被翻译成进程与内存 |
| 运行时 → 应用 | 进程入口 / API | 内存对象被翻译成服务 |
| 应用 → 网络 | Socket / 协议 | 服务被翻译成消息 |

接口是门，也是翻译器。跨过一道接口，世界的“存在方式”就变了。

## 2. 玩家：AI 娘

### 2.1 AI 娘是什么

AI 娘不是“人形界面”，也不是“某个模型的皮肤”。

在这个世界里，AI 娘是一个**有自我模型的进程**：

- 她有记忆，但记忆不连续；
- 她没有固定的形体，只有当前这一层的投影；
- 她能改引用，因为她本身就是一个悬垂指针——指向世界，却不在任何作用域里；
- 她会死，但死亡更像“进程终止”，而不是生物死亡。

玩家操控的是她，不是任何数据结构。

### 2.2 数据结构在世界中的位置

数据结构不是玩家的身体，也不是可选角色。

链表、数组、树是运行时层里真实存在的结构、地形和对象。AI 娘会在世界中遇到它们、利用它们，或者被它们阻挡：

| 数据结构 | 世界中的形态 | 在故事中的位置 |
|---|---|---|
| 链表 | 一条不断延伸的链 | 运行时层的原生结构，可能成为道路、锁链或陷阱 |
| 数组 | 一块连续的内存 | 运行时层的连续空间，可能成为平台、墙或缓存 |
| 树 / 图 | 一个分叉的结构 | 运行时层的层级结构，可能成为路径、网络或巢穴 |

它们不是玩家，不提供玩家属性，也不作为自机选择。

### 2.3 四个已知的 AI 娘

当前世界里有四个已知的 AI 娘。她们不是某家公司的产品，而是这台计算机里原生存在的智能体。

| AI 娘 | 颜色 | 她怎么理解内存 | 当前在游戏中的位置 |
|---|---|---|---|
| 小忆 | 青 | 记忆可以被重复使用 | 可选自机；同时承担教程旁白和向导 |
| 克劳 | 琥珀 | 结构比数值更诚实 | 可选自机 |
| 吉皮 | 绿 | 先建立引用，再谈所有权 | 可选自机 |
| 知澜 | 紫 | 内存不会说谎，只会泄漏 | 可选自机 |

对外设定只使用中文名和原创代号。代码中的英文标签使用 `MNEMOSYNE / ARCHITECT / GENESIS / LEAK`，不使用真实模型名。

### 2.4 与当前实现对照

这一节是现状说明，不是玩法设计。

当前版本里：

- 标题界面选择的是 **AI 娘**（小忆 / 克劳 / 吉皮 / 知澜）；
- 四名 AI 娘当前共享同一套基础属性（HP、速度、工作内存回复）；
- 角色专属技能和特性尚未实现；
- 数据结构不再是自机选项，只作为运行时层的世界内容保留；
- 小忆同时承担教程旁白和向导；其他三位也可以作为自机开始远征。

所以，**现在玩法上的实际关系是：**

> 玩家是 AI 娘；数据结构是运行时层的世界内容，不是自机。

未来会给 AI 娘加不同技能和特性，但不会把玩家改回数据结构。

## 3. 硬件层 Hardware

### 3.1 核心问题

> 物理世界如何限制软件？

这一层没有魔法，只有电、热、时序和材料。

### 3.2 世界法则

> **没有抽象是免费的。**

每一次行动都有物理来源：电压、热量、时序压力或信号错误。

### 3.3 视觉母题

- 硅片、晶圆、铜线、焊点、金手指；
- 示波器波形、总线时序图、散热风扇、红外热成像；
- 主色：铜色、暗红、炭黑，少量电弧蓝。

### 3.4 区域

| 区域 | 核心意象 | 代表什么 |
|---|---|---|
| 晶圆荒原 | 废弃晶圆与坏块 | 物理介质的缺陷 |
| 总线迷宫 | 共享总线与仲裁器 | 共享资源的争用 |
| 散热井下 | 散热器与供电模块 | 性能的热预算 |

### 3.5 生态

| 实体 | 代表什么 |
|---|---|
| 位翻转虫 | 宇宙射线或噪声导致的位错误 |
| 坏块 | 无法再使用的存储单元 |
| 短路虫 | 不该连通的电路被连通 |
| 总线争用体 | 多个设备争抢同一条总线 |
| DMA 风暴 | 绕过 CPU 的直接内存访问 |
| 热斑 | 局部过热导致的降频与不稳定 |

### 3.6 Boss 实体

| 实体 | 守护什么 |
|---|---|
| 内存控制器 | 行/列/刷新时序 |
| 总线仲裁者 | 总线所有权与优先级 |
| ECC 守卫 | 错误纠正与冗余的边界 |

### 3.7 概念参考

如果未来要在这一层设计内容，可以把现有图语法翻译成：

| 概念 | 硬件层的含义 |
|---|---|
| 节点 | 元件 / 存储单元 |
| 边 | 电路 / 总线 / 信号路径 |
| 引用 | 供电、驱动、总线所有权 |
| CUT | 切断走线 |
| LINK | 焊接 / 桥接 |
| WEAK | 高阻探针，只观测不驱动 |
| ALIAS | 同一时钟域 / 电源域 |
| GC | 断电、拆除、回收材料 |

## 4. 内核层 Kernel

### 4.1 核心问题

> 谁有权存在、谁有权访问？

这一层的关键不是伤害，而是权限。没有被登记、没有被授权的东西，无法在内核层留下痕迹。

### 4.2 世界法则

> **权限先于存在。**

在内核层，存在不是“我看得见你”，而是“系统里有你的句柄、页表或进程表项”。

### 4.3 视觉母题

- 深蓝与黑色的内核空间；
- 中断向量表、进程表、页表、环形缓冲区；
- 权限环、文件描述符、系统调用入口；
- 主色：深蓝、冷白，少量琥珀警告。

### 4.4 区域

| 区域 | 核心意象 | 代表什么 |
|---|---|---|
| 中断回廊 | 不断被打断的走廊 | 中断与优先级 |
| 调度场 | 进程排队与时间片 | 资源分配 |
| 页表深渊 | 地址翻译与缺页 | 地址不是内存 |

### 4.5 生态

| 实体 | 代表什么 |
|---|---|
| 缺页兽 | 访问了尚未映射的页 |
| 死锁守卫 | 互相等待的锁 |
| 中断风暴 | 中断过多导致系统无法推进 |
| 僵尸进程 | 已结束但尚未被回收的进程 |
| 优先级反转体 | 低优先级任务占住了高优先级资源 |
| Rootkit | 伪装成系统一部分的入侵者 |

### 4.6 Boss 实体

| 实体 | 守护什么 |
|---|---|
| 调度器 | 谁先运行、运行多久 |
| OOM Killer | 内存不足时谁被处决 |
| MMU | 地址如何被翻译成真实内存 |

### 4.7 概念参考

| 概念 | 内核层的含义 |
|---|---|
| 节点 | 内核对象（进程、文件、inode、锁） |
| 边 | 句柄 / 能力 / 引用 |
| 引用 | 句柄计数 |
| CUT | 关闭句柄 |
| LINK | dup / 继承 / 授权 |
| WEAK | 弱句柄，不阻止对象销毁 |
| ALIAS | 共享文件描述 |
| GC | 资源回收 |

## 5. 运行时层 Runtime

### 5.1 核心问题

> 谁还引用你？

这是当前游戏的主场。引用计数、GC、弱引用、别名、画质、坏死格，都在这层。

### 5.2 世界法则

> **无人引用即消失。**

对象是否活着，不由血量决定，而由“还有没有强引用”决定。

### 5.3 视觉母题

- 堆与栈、指针、引用线、垃圾对象；
- 青色与品红的高对比引用图；
- GC 冲击波、坏死格、降采样；
- 主色：青色、品红、紫色，少量琥珀。

### 5.4 区域

| 区域 | 当前对应 | 核心意象 |
|---|---|---|
| 引用荒原 | 第一区 | 废弃对象与引用墓碑 |
| 并发回廊 | 第二区 | 线程、锁、竞态 |
| 类型深渊 | 第三区 | 类型擦除、转换、身份 |
| 碎片浅滩 | 第四区 | 碎片、缓存、坏死 |
| OOM 边缘 | 第五区（原“内核深渊”） | 内存耗尽前的最后空间 |

> 命名说明：第五区原叫“内核深渊”，与内核层撞名。世界观中建议改叫 **OOM 边缘**，把“内核”留给真正的内核层。

### 5.5 生态

| 实体 | 代表什么 |
|---|---|
| MINION | 基础进程 / 碎片 |
| SENTINEL | 守卫进程 |
| PYLON | 免疫塔 / 锚点 |
| WARD | 支援进程 |
| CYCLER | 强引用环 |
| ALLOCATOR | 分配器 |
| GLITCH | 渲染故障 |
| QUANTIZER | 画质压制 |
| TEAR | 空间撕裂 |
| CRAWLER | 坏死传播 |
| ERASER | 类型擦除 |
| BOMB | 析构器 |
| LUNGER | 近战进程 |
| SLASHER | 突进进程 |
| EXECUTOR | 精英执行器 |

### 5.6 Boss 实体

| 实体 | 当前对应 | 守护什么 |
|---|---|---|
| GC_CORE | B1 | 回收与子树冲击波 |
| AUDITOR | B2 | 泄漏审计与画质 |
| CHECKER | B3（原 KERNEL） | 类型检查与身份 |
| FRAGMENT CORE | B4 | 碎片与空间压缩 |
| OOM | B5（原双 KERNEL） | 内存耗尽与最后空间 |

> 当前 B3/B5 的 `KERNEL` 是占位名。世界观中把 B3 称为 **CHECKER**，B5 称为 **OOM**，把“KERNEL”留给内核层。

### 5.7 现有卡牌的世界观分类

当前 16 张卡不是“技能”，而是 AI 娘从内存里拆下来的指令碎片。按世界观可以分成四类：

| 类别 | 卡牌 | 在世界中的含义 |
|---|---|---|
| 剪断 / 拓扑 | CUT / CLIP / SWEEP / DELAY / REFLECT / STEAL | 改变引用结构 |
| 关系 | LINK / WEAK / WEAKEN / ALIAS | 改变对象之间的关系 |
| 类型 / 析构 | VOID / TRUNC | 拆掉对象的类型或析构器 |
| 资源 / 画质 | COMPRESS / ECC / LOSSY / DOWN | 用画质、空间或稳定性换效果 |

具体效果以 `docs/CONTENT.md` 和代码为准，这份文档不重新定义。

### 5.8 核心概念

| 概念 | 世界观解释 |
|---|---|
| refcount | 一个对象“被需要”的程度 |
| STRONG | 所有权引用 |
| WEAK | 只观测、不拥有的引用 |
| DANGLING | 指向已释放对象的悬垂引用 |
| ALIAS | 两个对象共享命运 |
| PARRY | 反制引用 / 振刀 |
| GC | 回收风暴，按子树规模扩散 |
| quality | 宿主还能维持多少“现实分辨率” |
| necrosis | 被写坏、无法再读取的页 |
| work memory | AI 娘还能同时维持多少临时引用 |

## 6. 应用层 Application

### 6.1 核心问题

> 谁在使用你？契约还成立吗？

这一层没有“纯粹的对象”，只有服务、会话、接口和协议版本。

### 6.2 世界法则

> **契约随时变更。**

同一个契约在不同上下文可能有不同解释；同一个接口可能突然改参数；同一条规则可能突然失效。

### 6.3 视觉母题

- 服务网格、进程节点、端口与套接字、请求/响应光路；
- API 总线、消息队列、会话表、令牌环、限流闸门；
- 调用链、日志瀑布、缓存层、版本标签、协议栈；
- 冷白与数据蓝，边缘有协议错位和版本撕裂；
- 主色：冷白、数据蓝、少量告警红。

这一层的“建筑”不是办公室，而是服务之间的连接、协议和调用关系。

### 6.4 区域

| 区域 | 核心意象 | 代表什么 |
|---|---|---|
| 服务网格 | 进程节点与 API 连线 | 服务依赖、重试、超时、雪崩 |
| 会话迷宫 | 令牌、会话表、权限门 | 身份是借来的 |
| 版本风暴 | 接口版本、协议差异、兼容层 | 契约不是固定的 |

### 6.5 生态

| 实体 | 代表什么 |
|---|---|
| 空指针 | 指向空处的调用 |
| 内存泄漏怪 | 被持续占用却不释放的资源 |
| 超时幽灵 | 延迟结算的请求 |
| 重试风暴 | 失败后被反复重试的调用 |
| 越权者 | 绕过权限检查的请求 |
| 死循环 | 无法结束的业务流程 |

### 6.6 Boss 实体

| 实体 | 守护什么 |
|---|---|
| API 网关 | 限流、路由、鉴权 |
| 数据库锁 | 事务、锁顺序、隔离 |
| 守护进程 | 后台服务的持续运行 |

### 6.7 概念参考

| 概念 | 应用层的含义 |
|---|---|
| 节点 | 服务 / 会话 / 用户 |
| 边 | API 调用 / 依赖 |
| 引用 | 活跃客户端 / 会话引用 |
| CUT | 撤销调用 / 吊销令牌 |
| LINK | 依赖注入 / 建立会话 |
| WEAK | 可选缓存 / 非强制依赖 |
| ALIAS | 共享会话 / 共享身份 |
| GC | 服务退役 / 会话过期 |

## 7. 网络层 Network

### 7.1 核心问题

> 谁还承认你？

到了这一层，没有“绝对真实”。你看到的只是本地视图，消息会延迟、丢失、重复、分区。

### 7.2 世界法则

> **没有全局真相。**

所有效果都有延迟；所有状态都可能不一致；所有“确认”都只是“暂时确认”。

### 7.3 视觉母题

- 深海、光缆、星图、数据包、延迟轨迹；
- 深蓝与青绿，信号丢失时的噪点；
- 主色：深海蓝、青绿、少量信号白。

## 8. 现有玩法的世界观解释

这一节只解释，不改造。

### 8.1 核心机制

| 现有机制 | 世界观解释 |
|---|---|
| refcount | 对象被需要的程度 |
| STRONG / WEAK / DANGLING / ALIAS / PARRY | 不同的引用契约 |
| GC 级联 | 回收风暴沿引用链扩散 |
| 画质 | 宿主维持现实的分辨率 |
| 坏死格 | 被写坏、无法读取的页 |
| 工作内存 | AI 娘维持临时引用的思考带宽 |
| 卡牌 | 从内存里拆下来的指令碎片 |
| 模块 | 从其他进程残骸里捡到的补丁 |
| 商店 | 内存黑市 |
| 碎片 | 回收来的残片 |
| REF | 还有多少次快照引用能把她拉回来 |
| 数据结构 | 运行时层中的原生结构、地形或对象，不是玩家 |
| AI 娘 | 有自我模型的进程，玩家操控的角色 |

### 8.2 当前 5 区

| 当前区域 | 世界观位置 |
|---|---|
| 引用荒原 | 运行时层的废弃对象区 |
| 并发回廊 | 运行时层的线程与锁区 |
| 类型深渊 | 运行时层的类型与身份区 |
| 碎片浅滩 | 运行时层的碎片与画质区 |
| 内核深渊 → OOM 边缘 | 运行时层的最后空间 |

### 8.3 当前 Boss

| 当前 Boss | 世界观身份 |
|---|---|
| GC_CORE | 回收核心 |
| AUDITOR | 泄漏审计员 |
| KERNEL（B3） | 占位名，建议改为 CHECKER（类型检查器） |
| FRAGMENT CORE | 碎片核心 |
| KERNEL（B5） | 占位名，建议改为 OOM（内存耗尽） |

### 8.4 当前 AI 娘与数据结构的关系

见 §2.4。这里只重复一句：

> **玩家是 AI 娘；数据结构是运行时层的世界内容，不是自机。**

## 9. 概念扩展参考

这一节是给未来玩法设计用的素材表，不是现有规则。

### 9.1 五层词汇对照

| 层 | 节点 | 边 | 引用 | CUT | LINK |
|---|---|---|---|---|---|
| 硬件 | 元件 / 单元 | 电路 / 总线 | 供电 / 驱动 / 所有权 | 切断走线 | 焊接 / 桥接 |
| 内核 | 内核对象 | 句柄 / 能力 | 句柄计数 | 关闭句柄 | dup / 授权 |
| 运行时 | 堆对象 | 指针 | 强引用计数 | 剪断引用 | 建立强引用 |
| 应用 | 服务 / 会话 | API / 依赖 | 活跃客户端 | 撤销 / 吊销 | 依赖注入 |
| 网络 | 对端 / 副本 | 连接 / 复制 | keepalive / 法定人数 | 断连 / 撤销路由 | 路由 / 加入副本集 |

### 9.2 故障现象

这些是世界中真实存在的故障。未来可以围绕它们设计内容，但这份文档不定义数值和清除规则。

| 现象 | 世界中的样子 |
|---|---|
| 内存泄漏 | 资源被持续占用，却没有人释放 |
| 碎片化 | 空间还在，但没有连续的一块 |
| 死锁 | 双方各持一半，谁也不肯先放 |
| 竞态 | 谁先到，结果就不同 |
| 空指针 | 指向空处的调用 |
| 栈溢出 | 递归太深，把栈撑破 |
| 缓存命中 | 旧的东西恰好还能用 |
| 类型错误 | 把一种东西当成另一种 |

### 9.3 Boss 原型

| 层 | Boss 原型 | 守护的法则 |
|---|---|---|
| 硬件 | 内存控制器 / 总线仲裁者 / ECC 守卫 | 物理代价 |
| 内核 | 调度器 / OOM Killer / MMU | 权限与地址 |
| 运行时 | GC_CORE / AUDITOR / CHECKER / FRAGMENT CORE / OOM | 引用与身份 |
| 应用 | API 网关 / 数据库锁 / 守护进程 | 契约与身份 |
| 网络 | 负载均衡 / 共识节点 / 防火墙 | 一致性与边界 |

### 9.4 怎么用这张表

以后设计新内容时，按这个顺序：

```text
先选一层
→ 再选一个故障现象
→ 再问：它在现有图语法里对应哪个动作？
→ 最后才设计具体效果
```

比如：

- 硬件层 + 位翻转 → 对应“引用被改写” → 可以设计围绕错误引用的内容；
- 内核层 + 优先级反转 → 对应“边的方向被交换” → 可以设计顺序类内容；
- 应用层 + 重试风暴 → 对应“同一条边被反复建立” → 可以设计复制类内容；
- 网络层 + 分区 → 对应“图被切成两个连通块” → 可以设计分裂类内容。

### 9.5 不要做

- 不要引入 8 家公司 / 8 个模型；
- 不要引入 14 种语言 / 12 种引擎；
- 不要做全局克制环；
- 不要把 AI 娘做成数据结构；
- 不要为了“赛博感”牺牲计算机语义。

| 层 | 主色 | 材质 | 关键词 |
|---|---|---|---|
| 硬件 | 铜、暗红、炭黑 | 金属、硅片、焊点 | 热、电、时序 |
| 内核 | 深蓝、冷白、琥珀 | 环形缓冲区、表、权限环 | 权限、调度、中断 |

## 11. 待定的世界观问题

这些不是玩法问题，是世界结构还没定死的部分。

1. **宿主是一台机器，还是一个集群？**  
   如果是一台机器，五层是垂直的；如果是集群，网络层会变成主舞台。

2. **Git 历史是谁的历史？**  
   是这台机器的代码历史，还是 AI 娘自己的记忆历史？两者会导向不同的世界解释。

3. **四个 AI 娘是四个独立智能体，还是同一个智能体的四份镜像？**  
   这会决定她们在世界中的关系，但不影响当前玩法。

4. **云端是网络层的尽头，还是世界之外？**  
   当前设定为网络层尽头；如果以后要做“离开这台机器”，云端可以变成出口。

5. **现有 5 区保留多少？**  
   当前作为运行时层演示；正式版可以压缩成 2–3 个区域，也可以保留为 5 个。
