# 《悬垂：内存远征》初步完整设计

> 版本：v0.1 初步设计稿  
> 日期：2026-11-22  
> 状态：世界与系统骨架，未进入剧情、数值和具体关卡实现  
> 范围：世界层、玩家层、Git 地图、战斗语法、内容管线、经济与落地顺序  
> 不含：剧情、对话、角色关系、最终平衡数值、美术终稿

---

## 0. 阅读说明

### 0.1 一句话概括

> 一台计算机的五个抽象层，加上一棵 Git 提交树；玩家操控 AI 娘，从硬件层向网络层推进。

### 0.2 这份文档解决什么

这份文档只解决“世界怎么分层、玩家是谁、地图怎么走、内容怎么长”四个问题。

它不解决：

- 具体剧情和角色关系；
- 每一张卡的最终数值；
- 每一个房间的敌人编成；
- 美术终稿和音频设计；
- 商业化、发行和运营。

### 0.3 五条设计原则

1. **每个名词都能在真实计算机里找到对应物。**  
   不做“随便套一层赛博皮”的奇幻设定。

2. **一层只教一个核心问题。**  
   层法则、敌人、Boss、区域规则都围绕同一个问题，不堆砌。

3. **一套图语法，五层词汇。**  
   节点、边、引用计数、GC、CUT、LINK 不重做，只换每层的名词和故障。

4. **AI 娘是角色，数据结构是机体。**  
   玩家操控的是人，不是链表、数组或树。

5. **Git 不是 UI 皮肤，是地图规则。**  
   每个 Git 操作都要有玩法代价，不能只是换一个图标。

### 0.4 与旧方案的关系

旧文档《三、设定扩展（世界·公司·语言·引擎·算法·敌人）》里，值得借的是结构，不是那套公司、语言和引擎内容。

**借：**

- 世界层栈与“每层一个区域规则”；
- 复杂度 = 费用；
- 专杀标签，不做全局克制环；
- 每个选择必须有明确坏处；
- 状态词典；
- 敌人和 Boss 各教一件事；
- 终端日志、数字可见的表现原则。

**不借：**

- 8 家公司 / 8 个模型戏仿；
- 14 种语言 / 12 种引擎的大表；
- 全局克制环；
- “旧版本的你”这类叙事内核；
- 把云端单独做成第六层的做法。

## 1. 世界总览

### 1.1 五层结构

```text
┌────────────────────────────────────────────┐
│ 5  网络层 Network                          │
│    没有全局真相：延迟、丢包、分区、共识      │
├────────────────────────────────────────────┤
│ 4  应用层 Application                      │
│    契约随时变更：API、会话、需求、权限       │
├────────────────────────────────────────────┤
│ 3  运行时层 Runtime                        │
│    无人引用即消失：引用、GC、类型、画质      │
├────────────────────────────────────────────┤
│ 2  内核层 Kernel                           │
│    权限先于伤害：句柄、调度、中断、页表      │
├────────────────────────────────────────────┤
│ 1  硬件层 Hardware                         │
│    没有抽象是免费的：电路、总线、时序、散热  │
└────────────────────────────────────────────┘
```

推进方向：**硬件层 → 内核层 → 运行时层 → 应用层 → 网络层**。

越往下，规则越硬，怪物越像物理故障；越往上，规则越软，怪物越像行为和语义。

“云端”不单独做第六层，它是网络层的尽头/终局区域。这样既保留云端内容，又避免网络层和云端层职责重叠。

### 1.2 每一层的标准内容包

每一层都必须包含以下内容，缺一不可：

| 内容 | 作用 |
|---|---|
| 层法则 | 这一层唯一一条全局规则 |
| 核心问题 | 玩家在这一层要回答的问题 |
| 视觉母题 | 一眼能认出“换层了” |
| 2–3 个区域 | 每层的内容分区 |
| 敌人标签 | 这一层敌人的共同弱点 |
| 普通敌人 | 教玩家一个动作或判断 |
| 层 Boss | 教玩家一条层法则 |
| 专属卡牌/模块 | 这一层的新解法 |
| 层间接口 | 通往下一层的门 |

### 1.3 层间接口

层与层之间不是“走楼梯”，而是一个**接口房间**：

| 接口 | 形式 | 作用 |
|---|---|---|
| 硬件 → 内核 | 引导程序 / ABI | 把物理信号翻译成系统调用 |
| 内核 → 运行时 | 加载器 / 系统调用 | 把权限翻译成进程与内存 |
| 运行时 → 应用 | 进程入口 / API | 把内存对象翻译成服务 |
| 应用 → 网络 | Socket / 协议 | 把服务翻译成消息 |

玩家通过层 Boss 后，在接口房间选择一项**层特权**带入下一层。层特权就是现在的“Boss 规则”的扩展版本。

## 2. 硬件层 Hardware

### 2.1 核心问题

> 物理世界如何限制软件？

这一层没有“魔法”，只有电、热、时序和材料。所有效果都要有一个物理来源。

### 2.2 层法则

> **没有抽象是免费的。**

每一次出牌、每一次移动、每一次链接，都会产生物理代价：热量、功耗、时序压力或信号错误。

### 2.3 视觉母题

- 硅片、晶圆、铜线、焊点、金手指；
- 示波器波形、总线时序图、散热风扇、红外热成像；
- 主色：铜色、暗红、炭黑，少量电弧蓝。

### 2.4 区域

| 区域 | 核心意象 | 主要故障 | 教学重点 |
|---|---|---|---|
| 晶圆荒原 | 废弃晶圆与坏块 | 位翻转、坏扇区、卡死单元 | 信号会错，错误会传播 |
| 总线迷宫 | 共享总线与仲裁器 | 总线争用、DMA 风暴、信号反射 | 共享资源要排队 |
| 散热井下 | 散热器与供电模块 | 过热、降频、电压跌落 | 性能有热预算 |

### 2.5 敌人生态

| 敌人 | 标签 | 行为 | 教什么 |
|---|---|---|---|
| 位翻转虫 | 硬件 / 信号 | 每次受击随机改变一个数字 | 不要相信绝对数值 |
| 坏块 | 硬件 / 存储 | 死亡后留下不可用格 | 空间会被永久破坏 |
| 短路虫 | 硬件 / 信号 | 死亡时向相邻节点放电 | 清理顺序很重要 |
| 总线争用体 | 硬件 / 时序 | 同时占用多个目标，抢行动顺序 | 共享资源要抢 |
| DMA 风暴 | 硬件 / 时序 | 绕过前排直接攻击后排 | 不是所有攻击都走同一条路 |
| 热斑 | 硬件 / 热 | 每回合升温，过热后自爆 | 不能拖太久 |

### 2.6 Boss 原型

| Boss | 机制 | 教什么 |
|---|---|---|
| 内存控制器 | 按行/列刷新，玩家必须在刷新窗口内输出 | 节奏与窗口 |
| 总线仲裁者 | 发放/收回总线令牌，没有令牌不能出牌 | 权限与排队 |
| ECC 守卫 | 自动纠正错误，玩家必须制造它纠正不过来的错误 | 冗余不是无敌 |

### 2.7 关键词与卡牌方向

| 关键词 | 效果方向 |
|---|---|
| 位翻转 | 随机改变一个数值或目标 |
| 坏块 | 永久占用一个格子 |
| 时序 | 在特定窗口内才生效 |
| 过热 | 连续使用同一类卡会升温 |
| ECC | 修正错误，但有上限 |
| DMA | 绕过路径限制 |
| 总线争用 | 双方争夺同一个行动槽 |

卡牌方向示例：`REFRESH`（刷新一行，清除坏死）、`PARITY`（校验并修正一次错误）、`DMA`（绕过目标选择限制）、`OVERCLOCK`（本回合加速，之后过热）、`SOLDER`（把两个节点焊成强引用）。

### 2.8 这一层教什么

> **所有抽象都有物理成本。**

玩家在硬件层学会：不要只看效果，要看代价；不要只看当前，要看窗口；不要相信“稳定”，要留冗余。

## 3. 内核层 Kernel

### 3.1 核心问题

> 谁有权存在、谁有权访问？

这一层的关键不是伤害，而是权限。没有句柄、没有权限、没有地址，就什么都做不了。

### 3.2 层法则

> **权限先于伤害。**

玩家必须先获得“可操作权”，才能对目标产生效果。越权操作会被弹回，甚至反噬。

### 3.3 视觉母题

- 深蓝与黑色的内核空间；
- 中断向量表、进程表、页表、环形缓冲区；
- 权限环、文件描述符、系统调用入口；
- 主色：深蓝、冷白，少量琥珀色警告。

### 3.4 区域

| 区域 | 核心意象 | 主要故障 | 教学重点 |
|---|---|---|---|
| 中断回廊 | 不断被打断的走廊 | 中断风暴、优先级反转 | 打断是有代价的 |
| 调度场 | 进程排队与时间片 | 饥饿、抢占、优先级 | 资源分配不是平均 |
| 页表深渊 | 地址翻译与缺页 | 缺页、越界、地址错乱 | 地址不是内存 |

### 3.5 敌人生态

| 敌人 | 标签 | 行为 | 教什么 |
|---|---|---|---|
| 缺页兽 | 内核 / 内存管理 | 每次受击召唤一个页错误 | 处理副作用 |
| 死锁守卫 | 内核 / 调度 | 锁住一个目标，必须按顺序解 | 顺序就是解法 |
| 中断风暴 | 内核 / 中断 | 每回合打断玩家一次出牌 | 留出缓冲 |
| 僵尸进程 | 内核 / 调度 | 死亡后仍占一个位置，下一回合才消失 | 死亡不等于清场 |
| 优先级反转体 | 内核 / 调度 | 低优先级目标抢走高优先级行动 | 优先级会骗人 |
| Rootkit | 内核 / 权限 | 伪装成友方，直到被审计 | 不是所有友军都是友军 |

### 3.6 Boss 原型

| Boss | 机制 | 教什么 |
|---|---|---|
| 调度器 | 改变行动顺序和时间片，玩家必须利用优先级 | 顺序是资源 |
| OOM Killer | 周期性处决“分数最低”的目标，玩家要提高自己的存在分 | 被需要才不被杀 |
| MMU | 把攻击重定向到错误地址，玩家必须建立正确映射 | 地址需要翻译 |

### 3.7 关键词与卡牌方向

| 关键词 | 效果方向 |
|---|---|
| 缺页 | 目标暂时不可用，处理后才恢复 |
| 中断 | 打断当前动作 |
| 优先级反转 | 行动顺序被交换 |
| 死锁 | 双方无法行动 |
| 句柄 | 获得一个临时操作权 |
| 权限环 | 决定能否使用某类卡 |
| 僵尸 | 死亡后仍占位 |

卡牌方向示例：`SYSCALL`（向系统请求一次效果，支付权限）、`MMAP`（临时开辟一格空间）、`SIGNAL`（打断一次敌方施法）、`FORK`（分裂一个临时分身）、`KILL`（处决低血量目标，但需要权限）。

### 3.8 这一层教什么

> **能做什么，取决于你有什么权限。**

玩家在内核层学会：先拿权限，再谈输出；先看顺序，再谈强度；不是所有目标都能直接打。

## 4. 运行时层 Runtime

### 4.1 核心问题

> 谁还引用你？

这是当前游戏的主场。引用计数、GC、弱引用、别名、画质、坏死格，都在这层。

### 4.2 层法则

> **无人引用即消失。**

对象是否活着，不由血量决定，而由“还有没有强引用”决定。

### 4.3 视觉母题

- 堆与栈、指针、引用线、垃圾对象；
- 青色与品红的高对比引用图；
- GC 冲击波、坏死格、降采样；
- 主色：青色、品红、紫色，少量琥珀。

### 4.4 区域

| 区域 | 当前对应 | 核心意象 | 教学重点 |
|---|---|---|---|
| 引用荒原 | 第一区 | 废弃对象与引用墓碑 | 被需要才存在 |
| 并发回廊 | 第二区 | 线程、锁、竞态 | 同时存在不等于属于你 |
| 类型深渊 | 第三区 | 类型擦除、转换、身份 | 你是什么由别人怎么解释 |
| 碎片浅滩 | 第四区 | 碎片、缓存、坏死 | 记忆不连续也能活 |
| OOM 边缘 | 第五区（原“内核深渊”） | 内存耗尽前的最后空间 | 存在的代价 |

### 4.5 敌人生态

当前 12 种普通敌人保留为运行时层基础生态，但需要按“教什么”重新归类：

| 敌人 | 教学重点 |
|---|---|
| MINION | 基础追击与清场 |
| SENTINEL | 远程威胁与掩体 |
| PYLON | 免疫与拆塔 |
| WARD | 护盾与优先击杀 |
| CYCLER | 强引用环 |
| ALLOCATOR | 召唤与场面膨胀 |
| GLITCH | 移动与不稳定 |
| QUANTIZER | 画质压制 |
| TEAR | 空间撕裂 |
| CRAWLER | 坏死格 |
| ERASER | 高血量与类型擦除 |
| BOMB | 析构器 |
| LUNGER | 近战与振刀 |
| SLASHER | 突进与蓄力 |
| EXECUTOR | 精英近战 |

不合适的敌人可以降级为区域特色，不强行保留全部。

### 4.6 Boss 原型

| Boss | 当前对应 | 机制 | 教什么 |
|---|---|---|---|
| GC_CORE | B1 | 回收风暴、子树冲击波 | 先清子节点 |
| AUDITOR | B2 | 审计泄漏、烧坏死格 | 画质是资源 |
| CHECKER | B3（原 KERNEL） | 类型检查、免疫错误类型 | 身份与类型 |
| FRAGMENT CORE | B4 | 碎片化、空间压缩 | 空间会碎 |
| OOM | B5（原双 KERNEL） | 内存耗尽、场地收缩 | 最后的空间 |

> 命名迁移：当前 B3/B5 的 `KERNEL` 与内核层撞名，建议改为 `CHECKER` / `OOM`。具体机制可以继承现有代码，先换叙事皮和 Boss 规则，再逐步重做。

### 4.7 关键词与卡牌方向

当前 16 张卡保留为运行时层核心牌组：

```text
CUT / LINK / WEAK / CLIP / SWEEP / WEAKEN / ALIAS / VOID
TRUNC / DELAY / REFLECT / STEAL / COMPRESS / ECC / LOSSY / DOWN
```

新增算法卡优先做“改变图结构”的牌，而不是继续加伤害：

- 拓扑引爆；
- 记忆化；
- 并查集；
- 二分检索；
- 回溯。

### 4.8 这一层教什么

> **存在不是属性，是关系。**

玩家在运行时层学会：剪断关系、建立关系、利用关系；血量只是结果，引用才是原因。

## 5. 应用层 Application

### 5.1 核心问题

> 谁在使用你？契约还成立吗？

这一层没有“纯粹的对象”，只有服务、会话、接口和需求。敌人会改变规则，玩家要处理“变化”。

### 5.2 层法则

> **契约随时变更。**

同一张卡在不同回合可能产生不同效果；同一个敌人可能中途换目标；同一个接口可能突然改参数。

### 5.3 视觉母题

- 写字楼、会议室、白板、便利贴、窗口、服务网格；
- 干净的冷白与蓝色，但边缘有撕裂和错位；
- 主色：冷白、天蓝、少量警告红。

### 5.4 区域

| 区域 | 核心意象 | 主要故障 | 教学重点 |
|---|---|---|---|
| 服务大厅 | 微服务与负载均衡 | 重试风暴、超时、雪崩 | 重试会放大问题 |
| 会话迷宫 | 登录、令牌、权限 | 越权、会话固定、身份冒用 | 身份是借来的 |
| 需求风暴 | 白板、需求变更、A/B 测试 | 目标变化、规则变化 | 目标不是固定的 |

### 5.5 敌人生态

| 敌人 | 标签 | 行为 | 教什么 |
|---|---|---|---|
| 空指针 | 应用 / 数据 | 50% 闪避，攻击落空 | 必中与校验 |
| 内存泄漏怪 | 应用 / 数据 | 每回合偷走一个资源 | 资源会慢慢漏 |
| 超时幽灵 | 应用 / API | 延迟结算，超时后反噬 | 时间也是资源 |
| 重试风暴 | 应用 / API | 死亡后分裂成两个更小的 | 不要无脑重试 |
| 越权者 | 应用 / 权限 | 无视一次控制效果 | 权限要验证 |
| 死循环 | 应用 / 逻辑 | 每回合回满血，除非被打断 | 有些东西不能靠伤害 |

### 5.6 Boss 原型

| Boss | 机制 | 教什么 |
|---|---|---|
| API 网关 | 限流、路由、鉴权，三阶段切换 | 先拿通行证 |
| 数据库锁 | 事务、锁顺序、隔离级别 | 顺序错就死锁 |
| 守护进程 | 死后重启，必须同时消灭所有实例 | 杀不干净等于没杀 |

### 5.7 关键词与卡牌方向

| 关键词 | 效果方向 |
|---|---|
| 超时 | 延迟生效，超时反噬 |
| 重试 | 重复上一次动作，费用递增 |
| 缓存 | 存储一张牌，下次免费 |
| 鉴权 | 获得一次越权操作 |
| 回滚 | 撤销一次事务 |
| 限流 | 限制敌方行动次数 |
| 雪崩 | 一个失败引发连锁失败 |

卡牌方向示例：`RETRY`（重复上一张牌，费用递增）、`CACHE`（缓存一张牌）、`AUTH`（绕过一次权限）、`ROLLBACK`（撤销一次伤害/召唤）、`RATE LIMIT`（敌方本回合只能行动一次）。

### 5.8 这一层教什么

> **规则会变，契约会破。**

玩家在应用层学会：不要背固定答案；要观察条件；要留后手。

## 6. 网络层 Network

### 6.1 核心问题

> 谁还承认你？

到了这一层，没有“绝对真实”。你看到的只是本地视图，消息会延迟、丢失、重复、分区。

### 6.2 层法则

> **没有全局真相。**

所有效果都有延迟；所有状态都可能不一致；所有“确认”都只是“暂时确认”。

### 6.3 视觉母题

- 深海、光缆、星图、数据包、延迟轨迹；
- 深蓝与青绿，信号丢失时的噪点；
- 主色：深海蓝、青绿、少量信号白。

### 6.4 区域

| 区域 | 核心意象 | 主要故障 | 教学重点 |
|---|---|---|---|
| 丢包海域 | 数据包在海里丢失 | 丢包、抖动、重传 | 确认不是保证 |
| 分区峡谷 | 被切断的网络 | 分区、脑裂、选主 | 多数不等于正确 |
| 云端尽头 | 容器、编排、跨主机 | 复制、调度、遗留系统 | 没有唯一的主机 |

### 6.5 敌人生态

| 敌人 | 标签 | 行为 | 教什么 |
|---|---|---|---|
| 丢包虫 | 网络 / 延迟 | 攻击有概率丢失 | 命中不是必然 |
| 重传体 | 网络 / 延迟 | 死亡后延迟复活一次 | 确认需要时间 |
| 分区兽 | 网络 / 分区 | 把战场切成两个独立区域 | 全局状态不存在 |
| 脑裂双子 | 网络 / 共识 | 两个 Boss 都认为自己是真的 | 多数不等于正确 |
| 爬虫 | 网络 / 复制 | 每回合复制自己 | 复制会失控 |
| DDoS 潮 | 网络 / 流量 | 数量极多，低血量 | 范围清场 |

### 6.6 Boss 原型

| Boss | 机制 | 教什么 |
|---|---|---|
| 负载均衡 | 把伤害/目标重定向到其他节点 | 找到真正的核心 |
| 共识节点 | 需要争取多数票才能造成伤害 | 共识需要成本 |
| 防火墙 | 规则过滤，只有特定标签的卡能通过 | 不是所有解法都可用 |

### 6.7 关键词与卡牌方向

| 关键词 | 效果方向 |
|---|---|
| 延迟 | 效果延后结算 |
| 丢包 | 效果有概率失效 |
| 重传 | 失效后再次尝试 |
| 分区 | 战场被切分 |
| 共识 | 需要多数目标同意 |
| 限流 | 限制行动频率 |
| 复制 | 生成副本 |

卡牌方向示例：`RETRANSMIT`（延迟但必中）、`QUORUM`（多数目标生效）、`PARTITION`（切分敌群）、`ROUTE`（重定向一次攻击）、`FLOOD`（范围伤害，费用高）。

### 6.8 这一层教什么

> **你看到的，不一定是全部。**

玩家在网络层学会：接受不确定性；利用延迟；不要相信单一视角。

## 7. 云端尽头

云端不单独做一层，它是网络层的最终区域。

| 内容 | 设计 |
|---|---|
| 视觉 | 天空城、漂浮容器、跨主机光缆、暴雨 |
| 核心故障 | 编排错误、复制延迟、遗留系统、跨区不一致 |
| 敌人 | 容器幽灵、调度漂移、遗留巨石、跨区副本 |
| Boss | 遗留系统 / 编排者 / 旧版本容器 |
| 层法则延伸 | 没有唯一的主机，也没有唯一的“你” |

云端尽头的作用是给网络层一个收束，而不是再开一套新规则。

## 8. 玩家层

### 8.1 三层结构

```text
AI 娘（角色 / 意识）
  └─ 机体（运行时载体 / 外骨骼）
       └─ 武装（卡牌 / 模块 / Boss 规则）
```

玩家操控的是 AI 娘。机体决定基础属性，武装决定构筑。

### 8.2 四个 AI 娘

四个 AI 娘是原生智能体，不是“某公司的模型”。她们的差异来自“怎么理解内存”，不是来自公司阵营。

| AI 娘 | 她怎么理解内存 | 玩法方向 | 代价方向 |
|---|---|---|---|
| 小忆 | 记忆是可以被重复使用的 | 缓存、复读、回收 | 初始牌序更固定，随机性低 |
| 克劳 | 结构比数值更诚实 | 链接、拓扑、稳定 | 移动/转向更慢 |
| 吉皮 | 先建立引用，再谈所有权 | 复制、生成、随机应变 | 效果波动更大 |
| 知澜 | 内存不会说谎，只会泄漏 | 弱引用、画质、熵 | 血量/稳定性更低 |

具体技能和数值后置，但每个 AI 娘必须改变玩家对卡牌的评价，不能只是换皮。

### 8.3 三种机体

| 机体 | 定位 | 优势 | 代价 |
|---|---|---|---|
| 链表 | 轻、快、脆 | 移速高、冲刺远、工作内存回复快 | 血量最低 |
| 数组 | 厚、慢、稳 | 血量高、受击稳定 | 移速慢、工作内存回复慢 |
| 树 | 均衡 | 属性均衡、网格适应性强 | 没有极端优势 |

机体不是角色。换机体不改 AI 娘的身份和对话。

### 8.4 角色成长

- **人格补丁**：解锁 AI 娘的被动/卡牌倾向，不直接加数值。
- **机体许可**：解锁新的机体，不叠加旧机体属性。
- **记忆碎片**：局外解锁卡牌、模块、Boss 规则。
- **不做事**：不做永久属性刷取，不做等级压制。

成长应该让玩家“多一种打法”，而不是“多 10 点攻击”。

## 9. Git 地图

### 9.1 为什么是 Git

因为这张地图本身就是计算机世界的一部分：

- 每个房间是一次提交；
- 每条路线是一条分支；
- 每次合流是一次 merge；
- 每次反悔是一次 revert；
- 每个 Boss 是一个 tag。

地图不是“把 Git 画成树”，而是“玩家真的在提交历史里移动”。

### 9.2 节点结构

每个节点是一间房/一组房，建议字段：

```json
{
  "id": "R07-3",
  "layer": "runtime",
  "region": "type_abyss",
  "type": "feat",
  "danger": 6,
  "parents": ["R07-2"],
  "children": ["R08-1", "R08-2"],
  "enemies": ["GLITCH", "TEAR"],
  "reward_pool": ["card", "module"],
  "law_modifier": "type_error_chance_up",
  "message": "fix: type confusion in cast"
}
```

### 9.3 节点类型

| 类型 | 对应房间 | 作用 |
|---|---|---|
| `feat` | 普通战 | 基础推进 |
| `fix` | 精英战 | 更高危险度，更好奖励 |
| `test` | 挑战房 | 限定条件，额外奖励 |
| `docs` | 事件/商店 | 非战斗节点，提供信息或交易 |
| `merge` | 合流/Boss | 两条路线汇合，处理冲突 |
| `revert` | 回退房 | 撤销上一个节点，留下技术债 |
| `tag` | 里程碑 | Boss/存档点，永久解锁 |

### 9.4 核心操作

| Git 操作 | 玩法含义 | 代价 |
|---|---|---|
| `commit` | 清房通关，写入存档点 | 当前状态被写死，不能反悔 |
| `branch` | 路线分叉，选择不同区域/奖励 | 资源分散，错过另一条线 |
| `merge` | 两条路线合流 | 冲突二选一，或打双 Boss |
| `revert` | 回退一个节点 | 留下技术债/残留敌人，历史还在 |
| `tag` | Boss/里程碑 | 需要先打赢 |
| `checkout` | 在枢纽切换分支 | 需要“干净工作区”，不能带着未结算奖励 |
| `stash` | 暂存一张卡/模块 | 只能存一件，取出有代价 |
| `reflog` | 找回失败分支的残片 | 有限次数，不能找回全部 |

### 9.5 一局的结构

完整设计目标：

```text
5 层 × 每层 7–9 个节点 ≈ 35–45 个 commit
单局 60–90 分钟
```

每层内部：

```text
入口 → 2–3 个分支点 → 区域精英 → 层 Boss（tag）→ 层间接口
```

首个可玩版本只做运行时层：

```text
12–15 个节点，20–30 分钟
```

### 9.6 局外 Meta

- **main**：成功远征合入 main，永久解锁新层、新角色、新卡。
- **dangling branch**：失败远征留在提交图上，成为“悬垂分支”。
- **reflog**：有限次找回失败分支里的一件东西。
- **stash**：局外仓库，最多存一件。
- **tag**：Boss 里程碑，可快速跳转/解锁。

Meta 的原则：解锁“新选择”，不堆“永久数值”。

### 9.7 地图 UI

- 采用 `git log --graph` 的视觉语言；
- 节点写 commit message，例如 `fix: page fault in mmap`；
- 分支线按层着色；
- 当前节点标记 `HEAD`；
- 悬停显示 diff：敌人、奖励、层法则；
- 合流点显示冲突提示。

### 9.8 失败与重试

- 死亡 = 进程终止，不是剧情复活；
- 从上一个 `commit` 恢复；
- `REF` = 还能被重新引用的次数；
- `REF` 耗尽 = 本次远征结束；
- 使用 `revert` 回退会产生“技术债”，下一场出现残留敌人；
- 失败分支不会消失，留在图上，成为下一次的路线素材。

## 10. 战斗与内容语法

### 10.1 一套图语法，五层词汇

核心永远是：

```text
节点 Node + 边 Edge + 引用计数 refcount + GC
```

每层只换“节点/边/引用”指什么：

| 层 | 节点 | 边 | 引用是什么 | CUT 是什么 |
|---|---|---|---|---|
| 硬件 | 元件/单元 | 电路/总线 | 连通与驱动 | 切断走线 |
| 内核 | 内核对象 | 句柄/能力 | 句柄计数 | 关闭句柄 |
| 运行时 | 堆对象 | 指针 | 强引用计数 | 剪断引用 |
| 应用 | 服务/会话 | API 调用 | 活跃客户端 | 撤销调用/令牌 |
| 网络 | 对端/副本 | 连接/复制 | keepalive/复制因子 | 断连/撤销路由 |

这样 CUT / LINK / WEAK / ALIAS / GC 不需要重做，只需要换每层的名词、视觉和敌人。

### 10.2 卡牌分类

| 类别 | 例子 | 作用 |
|---|---|---|
| 核心动词 | CUT / LINK / WEAK | 所有层通用 |
| 层专属 | REFRESH / SYSCALL / RETRY | 体现层法则 |
| 算法卡 | 拓扑引爆 / 记忆化 / 并查集 | 改变图结构 |
| 资源卡 | COMPRESS / ECC / DOWN | 用资源换效果 |
| 模块 | 被动/触发 | 改变规则，不占手牌 |

### 10.3 复杂度 = 费用

| 复杂度 | 工作内存 | 形状 | 限制 |
|---|---:|---|---|
| O(1) | 0–1 | 1×1 | 无 |
| O(log n) | 1 | 1×1 / 1×2 | 短冷却 |
| O(n) | 1–2 | 1×2 / 2×1 | 正常 |
| O(n log n) | 2 | 2×2 | 中等 |
| O(n²) | 3 | 2×3 | 高费用 |
| O(2ⁿ) | 3+ | 2×3 / 3×2 | 每房一次 |

`++` 升级 = 编译优化：

- 复杂度降一档；或
- 形状缩小一格；或
- 工作内存 -1。

不是单纯 +伤害。

### 10.4 首批算法卡

| 卡 | 算法 | 效果方向 | 风险 |
|---|---|---|---|
| 拓扑引爆 | 拓扑排序 | 按依赖顺序引爆一条链，链越长收益越高 | 需要先构建长链 |
| 记忆化 | 记忆化搜索 | 重复上一张牌，额外工作内存 | 费用累积 |
| 并查集 | 并查集 | 合并两个引用组，共享伤害/死亡，可继续合并 | 被合并组一起受伤 |
| 二分检索 | 二分查找 | 弃掉牌堆一半，检索指定类型 | 弃牌不可逆 |
| 回溯 | 回溯 | 恢复最近 2 秒被剪断的一条边 | 需要记录边历史 |

### 10.5 标签系统

| 标签类型 | 例子 | 作用 |
|---|---|---|
| 敌人标签 | 内存 / 并发 / 类型 / 网络 | 说明它怕什么 |
| 卡牌标签 | 拓扑 / 引用 / 画质 / 检索 | 说明它擅长什么 |
| AI 娘标签 | 缓存 / 结构 / 生成 / 泄漏 | 说明角色倾向 |

命中标签给 +20%–30% 效果；不命中不惩罚。不做全局克制环，避免玩家背表。

### 10.6 状态词典

每个状态必须能被至少一种手段清除。

| 状态 | 来源 | 效果 | 清除 |
|---|---|---|---|
| 内存泄漏 | 应用/运行时 | 每回合最大生命 -1，可叠 | GC / 重启 |
| 碎片化 | 运行时/硬件 | 不能使用大形状卡 | 整理 / ECC |
| 死锁 | 内核/应用 | 双方 2 回合不能行动 | 拓扑 / 剪枝 |
| 竞态 | 运行时/应用 | 30% 目标随机 | 加锁 / 序列化 |
| 空指针 | 应用/运行时 | 下次攻击 50% 落空 | 类型检查 |
| 栈溢出 | 运行时 | 递归卡反噬 | 降低递归层数 |
| 缓存命中 | 应用/运行时 | 下一张牌免费 | 消耗后消失 |
| 类型错误 | 运行时 | 伤害类型随机 | 类型标注 |

### 10.7 敌人设计模板

每个敌人必须回答四个问题：

1. 它属于哪一层？
2. 它教玩家什么？
3. 玩家用什么动作反制？
4. 它死后留下什么？

```text
id:
layer:
tags:
lesson:
hp:
behavior:
counter:
death_effect:
```

### 10.8 Boss 设计模板

每个 Boss 必须回答：

1. 它执行哪条层法则？
2. 它分几个阶段？
3. 它的“解”是什么？
4. 它死后给什么层特权？

```text
id:
layer:
law:
phases:
puzzle:
privilege:
reward:
failure_lesson:
```

Boss 不是血厚的小怪。Boss 是这一层法则的守门人。

## 11. 经济与奖励

### 11.1 碎片

沿用当前经济：

| 来源 | 数量 |
|---|---:|
| 普通房 | +1 |
| Boss 房 | +3 |
| 完美清房 | +2 |
| 完美 + Boss | 叠加 |

### 11.2 商店

| 项目 | 费用 |
|---|---:|
| 卡牌 | 2–5 |
| 模块 | 5 |
| 修复 1 个坏死格 | 2 |
| 移除卡牌 | 按稀有度 |

### 11.3 卖卡

基础价格：`2 + 稀有度 × 2`；`++` 再 +3。不同层可以调整，但不做复杂汇率。

### 11.4 模块

- 当前 14 个模块保留为运行时层模块；
- 每层新增 3–5 个层专属模块；
- 模块不占网格，不参与画质；
- 每个模块必须有明确代价或限制。

### 11.5 Boss 规则 / 层特权

- 每个层 Boss 掉落一个“层特权”；
- 层特权改变全局规则，而不是加数值；
- 当前 5 条 Boss 规则可以作为运行时层特权的基础；
- 新层特权示例：硬件层“过热换输出”、内核层“多一个权限槽”、应用层“多一次重试”、网络层“延迟结算但必中”。

### 11.6 局外解锁

- 新 AI 娘；
- 新机体；
- 新卡牌/模块；
- 新层；
- 新 tag/起点。

不做永久属性树，不做战力数值膨胀。

## 12. 内容规模与落地顺序

### 12.1 内容规模目标

| 内容 | 完整设计目标 | 首个可玩 |
|---|---:|---:|
| 世界层 | 5 | 1（运行时） |
| 区域 | 12–15 | 5（现有，后续压成 2–3 区） |
| commit 节点 | 35–45 | 12–15（现有房间合并为节点） |
| 层 Boss | 5 | 1（运行时层） |
| Boss 房 | 5 | 5（现有） |
| 普通敌人 | 25–30 | 12–15（现有） |
| 卡牌 | 25–30 | 16 + 5 算法卡 |
| 模块 | 20–25 | 14 |
| AI 娘 | 4 | 4 |
| 机体 | 3 | 3 |

### 12.2 落地顺序

**阶段 0：设计冻结**

- 本文档定稿；
- 确定层序、角色差异、卡池方向；
- 不改代码。

**阶段 1：运行时层 + Git 地图原型**

- 现有 5 区压缩成运行时层；
- 加入 commit/branch/merge/revert/tag 的地图原型；
- 用现有 16 卡验证核心循环；
- 目标：20–30 分钟可玩。

**阶段 2：算法卡与复杂度费用**

- 先做 3 张：拓扑引爆、并查集、回溯；
- 验证“复杂度 = 费用”是否成立；
- 再补记忆化、二分检索。

**阶段 3：硬件层垂直切片**

- 1 个区域 + 1 个 Boss；
- 验证层法则、敌人标签、层特权；
- 不急着做完整五层。

**阶段 4：内核层**

- 复用运行时层的图语法；
- 加入权限/句柄/中断；
- 验证“权限先于伤害”。

**阶段 5：应用层与网络层**

- 先做应用层，再做网络层；
- 云端作为网络层终局；
- 最后再考虑 Meta 的完整形态。

### 12.3 明确不做

- 不做 8 家公司 / 8 个模型；
- 不做 14 种语言 / 12 种引擎；
- 不做全局克制环；
- 不做永久属性刷取；
- 不在世界规则稳定前写剧情；
- 不一次性做完五层再验证。

   当前建议：通用动词 + 每层 3–5 张专属。

4. **首版层数**：1.0 做 3 层还是 4 层？  
   当前建议：先做运行时层，再决定第二层是硬件还是内核。

5. **单局长度**：60 分钟还是 90 分钟？  
   当前建议：完整设计 60–90 分钟，首个可玩 20–30 分钟。

6. **英文型号**：代码里的 `DEEPSEEK / CLAUDE / GPT / GLM` 是否只保留为内部 ID？  
   当前建议：是，对外设定只用中文名/原创代号。
